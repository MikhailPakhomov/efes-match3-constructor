# EFES Match-3 — конструктор уровней

Локальное React + TypeScript приложение. Ассеты, `Match3Engine`, валидаторы и PixiJS-сцена скопированы из соседнего `efes-match3`; исходная игра не изменялась.

```sh
npm ci
npm run dev
```

Откройте адрес Vite в терминале. `npm run build` создаёт `dist`, `npm run preview` показывает сборку, `npm test` проверяет движок, операции редактора и совместимость JSON. `npm run lint` запускает ESLint.

## Возможности

- Размеры поля 1–7 по каждой оси, не менее четырёх активных клеток — ограничения исходного валидатора.
- Рисование кликом или протягиванием мышью; отмена и повтор последних 100 изменений.
- Все базовые фишки, пять хелперов, коробки, камни, отверстия, лёд в один или два слоя. Лёд сохраняет фишку или хелпер под собой.
- Автофишки заполняются движком по seed. Ластик «Автофишка» удаляет предустановку, «Снять лёд» удаляет только overlay.
- Цели, ходы, сложность, seed, набор генерируемых фишек и инвентарь бустеров.
- Импорт обоих форматов JSON, экспорт, просмотр JSON, локальное сохранение черновика.
- Тест уровня в исходном PixiJS-рендерере с исходными правилами, анимациями, целями и бустерами. Тест не вызывает API игры и не изменяет игровой профиль.
- Проверка схемы и создание движка перед экспортом/запуском: обнаруживает стартовые комбинации и неверные конфиги.

## Форматы и интеграция с бэкендом

**«Сохранить JSON»** выгружает полный `LevelConfig` версии 1 — тот же контракт, что `public/levels/demo.json` исходной игры: `schemaVersion`, `id`, `seed`, `cols`, `rows`, `mode`, `difficulty`, `moveLimit`, `targets`, `blocks`, `blockTypes`, `boosters`. Координаты `x`, `y` начинаются с нуля. Тип определяется через `blockTypes[].id`; предустановка ссылается на него через `blocks[].id`. Незаполненные позиции генерирует движок. Лёд — отдельный блок на тех же координатах с `hp` 1 или 2. Типы и их ID при импорте сохраняются.

**«Экспорт для текущего API»** в разделе интеграции формирует существующий серверный контракт `{ grid, moves, levelGoals }`. Он поддерживает только `blue → kozel`, `yellow → pineapple`, `red → cap`, `green → mill`, `violet → crown`, `HOLE` и `{ id: "ice", innerId: "blue" }` с одним слоем льда. Цели — только пять цветов. Экспорт материализует автофишки и проверяет результат через исходный `parseServerLevel`. Несовместимые элементы вызывают ошибку, данные не отбрасываются.

**Для загрузки уровней с хелперами через админку требуется расширение интеграции основного проекта.** Сейчас его `parseServerLevel` принимает только ограниченный формат. Бэкенд должен хранить полный JSON, а загрузчик игры выбирать валидатор:

```ts
const value: unknown = JSON.parse(levelData)
const config = value && typeof value === 'object' && 'schemaVersion' in value
  ? parseLevel(value)
  : parseServerLevel(levelData, order, gameId)
```

Это рекомендация для интеграции: в этом репозитории нет кода админки или бэкенда, и они не изменялись. Необходимо также согласовать ограничения загрузки JSON в админке. Редактор уже экспортирует полный контракт движка без собственной обёртки.

## Структура

- `src/features/editor/Editor.tsx` — UI и состояние редактора.
- `src/features/editor/model.ts` — редактирование, проверка, преобразование JSON.
- `src/features/editor/Playtest.tsx` — локальная тестовая сессия и воспроизведение кадров движка.
- `src/entities/match3` — копия домена исходной игры.
- `src/features/match3/pixi` — копия PixiBoard / BoardScene с управлением жизненным циклом canvas.
- `public/images/match3`, `public/levels/demo.json` — оригинальные ресурсы.

Для обновления правил следует синхронно переносить домен, Pixi-сцену, конфиги и соответствующие тесты из основной игры. React управляет редактором, HUD и модальным окном; Pixi отвечает за графику и жесты тестового поля. Закрытие теста размонтирует сцену и отменяет воспроизведение кадров. Каждый новый запуск создаёт отдельную сессию с тем же seed.
